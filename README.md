# Arcanum

To start your Phoenix server:

* Start the development database with `docker compose up -d --wait`
* Run `mix setup` to install and setup dependencies
* Start Phoenix endpoint with `mix phx.server` or inside IEx with `iex -S mix phx.server`

Now you can visit [`localhost:4000`](http://localhost:4000) from your browser.

PostgreSQL is available at `localhost:5432` with username `postgres`, password
`postgres`, and database `arcanum_dev`, matching `config/dev.exs`. These credentials
are for local development only. Database data persists in a Docker volume.
Stop PostgreSQL with `docker compose down`.

## Development emails

Open [`localhost:4000/dev/mailbox`](http://localhost:4000/dev/mailbox) to read
registration and login emails. Register an account first, then request a login
email using that account's email address. Refresh the mailbox to see new messages.
The local adapter does not send real email and stores messages in memory: restarting
the Phoenix server clears the mailbox. Emails generated by a separate `mix run`
process will not appear in the running server's mailbox.

Existing accounts receive a temporary `user_<id>` username when the username
migration runs. Change it on the account settings page.

New users choose a password (at least 12 characters) when opening their activation
email link. The account is confirmed and the password is set together, after email
ownership has been verified.

Ready to run in production? Please [check our deployment guides](https://phoenix.hexdocs.pm/deployment.html).

## Community URLs

Community URLs use `/communities/<name>` rather than database IDs. Names are
unique across the application (case-insensitive), including deleted communities;
spaces are URL-encoded. Renaming a community changes its URL. `new` and names
containing slashes are not allowed.

Run `mix ecto.migrate` to add the unique community-name index. Existing duplicate
names must be resolved before the migration can succeed; it does not rename data.

## Code quality

Run `mix credo --strict` for linting and `mix dialyzer` for type analysis.
Both tools are available in development and tests and run as part of
`mix precommit` alongside formatting and tests.

Dialyzer runs in the test environment so it also checks compiled test helpers.
Its first run builds a dependency type cache (PLT) and can take several minutes.
The cache is stored under the ignored `_build/` directory; later runs reuse it.

## Continuous integration

GitHub Actions runs on pushes and pull requests, and can also be started manually.
The workflow checks formatting, compiles without warnings, runs Credo and Dialyzer,
tests against PostgreSQL 17, and builds the frontend assets. It caches dependencies,
compiled code, and Dialyzer type information. CI uses Elixir 1.20.4 and Erlang/OTP
29.0.6, matching the current development environment.
